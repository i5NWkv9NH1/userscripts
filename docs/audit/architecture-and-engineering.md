# 工程构建与架构检查

## 1. 结论

项目基于 Bun 打包，配合原生 Web Components 和顶层 `popover` 实现界面，整体结构清晰、没有第三方运行时依赖。但在构建压缩、脚本运行上下文、跨脚本协作和组件生命周期上有 4 个主要问题：

1. **正则压缩 CSS 和 HTML 容易出错**：简单正则会把 CSS `calc()` 里的 `+` 两侧空格删掉，也会在属性值包含 `>` 时破坏 HTML。
2. **打包外壳注入主页面导致油猴接口丢失**：通过 `GM_addElement` 把脚本注入主页面上下文时，主页面里没有 `GM_getValue` 等接口，会直接报错；同时严格的网页 CSP 也会拦截内联脚本。
3. **跨脚本快捷键状态只存在局部内存里**：每个站点单独打成一个包，局部的 `Map` 和标志位互相看不见，多个脚本在同一网页运行时无法互相检测快捷键冲突。
4. **组件短暂移出页面就会被全部销毁重绘**：`disconnectedCallback` 触发彻底销毁并重置 `#rendered`，一旦组件被临时挪动位置，再插回页面时所有界面状态都会丢失。

## 2. 问题详情与改进方向

### 2.1 正则压缩模板字符串

在 `scripts/meta.ts` 中，旧版 `minifyCssString` 用正则删除 `+` 号两侧空白，会把 `calc(100% + 20px)` 变成无效语法；`minifyTaggedTemplatesInSource` 没有正确跳过注释和正则字面量。

- **改进做法**：CSS 压缩避开运算符号周围必要空格（保护 `calc()` 表达式里的加减号空白），取消危险的源码文本正则截断，交给 `Bun.build` 自身处理压缩；SVG 和独立 CSS 文件安全清理注释与多余空白即可。

### 2.2 生产构建脚本外壳

在 `scripts/build.ts` 中，旧版把代码用字符串包裹并尝试用 `GM_addElement` 塞进主页面。实际上本项目的脚本都需要使用 `GM_*` 存储或跨域请求，并且声明了 `@inject-into content`。直接输出标准 IIFE 产物，不要用 `b.toString()` 二次拼接运行。

### 2.3 多脚本独立打包导致的隔离问题

`aistudio`、`lens`、`playground` 各自独立运行在自己的脚本沙盒里。如果只是模块内 `const map = new Map()`，脚本 A 根本不知道脚本 B 占用了哪个快捷键、停靠在哪个角落。

- **改进做法**：通过挂载在共享 `document` 上的事件与记录协议（并配合 `window` 共享表），让同一网页里的多个脚本实时同步各自的快捷键、录制状态和悬浮窗口占用区域。

### 2.4 Web Components 挂载与卸载

`BaseComponent` 把「首次建好内部 DOM」和「每次挂载时绑定全局监听」混在一起。

- **改进做法**：内部 Shadow DOM 只建立一次；`disconnectedCallback` 只清理外部事件监听（保留内部节点与状态），再次插入页面时重新挂回监听即可，同时支持 `connectedMoveCallback`。
