# 性能与本地开发接口检查

## 1. 结论

运行时和开发网关存在 4 个明显的性能或接口规范问题：

1. **批量收集页面图片时反复触发布局重算**：画廊收集逻辑并发对数百张图片调用 `getBoundingClientRect()`，容易造成页面掉帧卡顿。
2. **查询文件大小时下载完整原图**：`HEAD` 请求拿不到 `content-length` 时，直接发起 `GET` 并读取完整 `blob()`，白白浪费用户流量和内存。
3. **AI 正在输出文字时高频扫描全页 DOM**：`useObserver(document.body, ...)` 在模型打字期间每帧反复执行全页节点查询与整理。
4. **本地开发网关接口返回不规范**：未知路径也返回 `200`、不检查请求方法、500 错误响应缺少跨域头、`HMR` 刷新通知不区分站点且动态 `import` 带时间戳会不断累积内存。

## 2. 改进方向

1. **图库收集避免强制同步重排**：优先根据 `naturalWidth`、`naturalHeight`、`src`、标签类型做筛选，不要对每张图片同步调用 `getBoundingClientRect()`。
2. **绝不为了显示文件大小去下载完整文件**：只发 `HEAD` 请求读取大小，拿不到就直接显示「未知大小」或省略，只有用户点下载时才拉取完整文件。
3. **AI Studio 观察逻辑增加防抖**：流式输出过程中把全量整理与导出抓取合并防抖（例如 250ms），避免每秒几十次全量遍历。
4. **规范本地开发网关**：
   - 未知路径返回 `404`，非 `GET` 请求返回 `405`。
   - 500 错误响应补齐跨域允许头，让浏览器看得到具体报错信息。
   - 按站点隔离长轮询等待集合，改了哪个站点只刷新哪个站点；清理没用上的 WebSocket 死代码；直接读取文件判断而非用带时间戳的 `import()`。
