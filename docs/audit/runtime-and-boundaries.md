# 运行时与边界情况检查

## 1. 结论

在跨域资源、中文输入法选词、侧边栏防误触和模板解析上存在 5 个边界问题：

1. **原生 `fetch` 下载跨域图片被拦截**：X (`pbs.twimg.com`) 等网站不开放任意跨域读取，`fetch(url)` 会直接失败，只能退化成新标签页打开。
2. **聊天导出遇到跨域图片画布被锁**：`canvas.toDataURL()` 报错被静默忽略，导出的文档里图片直接消失。
3. **输入法选词按回车误清草稿**：监听 `Enter` 键没检查 `ev.isComposing`（和 Safari 的 `keyCode === 229`），拼音打字按回车选词就把保存的草稿清掉了。
4. **防误触拦截范围太大**：把左侧栏里展开收起按钮等正常交互也拦截了，且只要聊天记录不为空就拦 `beforeunload` 关闭标签页。
5. **模板解析遇到属性里的 `>` 会错乱**：用 `lastOpen > lastClose` 判断是否在标签内部，遇到 `<button title="a > b">` 就会把后续事件绑定拆坏。

## 2. 改进方向

1. **优先用油猴接口请求和下载跨域资源**：`sites/lens/meta.ts` 补齐 `GM_xmlhttpRequest`、`GM_download` 和 `@connect *`，下载和文件头探测优先走油猴权限请求。
2. **导出图片失败不静默丢失**：优先用 `GM_xmlhttpRequest` 把跨域图片转成 Base64，实在转不了时在导出内容里保留图片原链接或文字提示。
3. **补全输入法状态判断**：`Enter` 清草稿前检查 `if (ev.isComposing || ev.keyCode === 229) return;`。
4. **收窄防误触判断条件**：只拦截实际会跳转页面的链接元素或带跳转行为的会话切换项；`beforeunload` 只在 AI 正在回答或输入框还有未发送草稿时提醒。
5. **用识别引号的扫描替代简单下标比较**：修改 `packages/core/dom/template.ts`，正确处理属性值中的 `<` 和 `>`。
